# 絶対に守るルール

このサイトを直したり足したりするときに、必ず守るルールです。ここに書いたことと食い違う変更をしたくなったら、先にこのファイルを更新してから作業します。

## コンセプト

- コンセプトは「夕暮れのベイエリア」です。函館山と金森赤レンガ倉庫のある港 (ベイエリア) の夕方を、インターネットの古い OS のウィンドウ越しに眺めます。
- 場面は函館山とベイエリアだけです。八幡坂の景色は描きません。八幡坂から取り入れるのは、ウィンドウの下に敷く不揃いな多角形の石畳と、中央の一本線だけです。
- ページの流れ: 夕焼けの空と函館山、元町、赤レンガ倉庫 (ヒーロー) → 港の水面 (下へ行くほど夜になり、イカが泳ぎ、カモメが飛ぶ) → 岸壁の石垣と市電の通り (otoneko.cat への入口) → 石畳のフッター。海は真ん中の1回だけにします。
- 秋の要素は控えめにします。季節に寄せすぎません。落ち葉は小さいとインベーダーに見えるので降らせません。
- 時間帯は夕方です。otoneko.cat (深夜の海) とずらします。
- 実在のものはリファレンスを確かめてから描きます。函館山は横に長くなだらかな「臥牛山」の形、市電は 800形 812号 (笹色ツートン、2枚引戸) をもとにします。
- インターネットの要素 (古い OS のウィンドウなど) は otoneko.cat と共通にし、並んだときに別の場所の同じ世界に見えるようにします。
- ウィンドウは otoneko.cat の見た目 (ドットの欠けた角、縞のタイトルバー、右上の3つのボタン、開くアニメーション) をそのまま使い、変えるのは配色だけです。
- 見た目はコンセプトに沿わせますが、文章はコンセプトに寄せすぎません。演出の言葉は入れません。

## 配色

文字やウィンドウの色は `src/styles/dusk.css` の `:root`、背景のドット絵の色は `src/data/scene.ts` にまとめます。ヒーローの水面、ページの水面、岸壁は同じ色でつなぎ、境目を見せません。

| トークン | 色 | イメージ |
| --- | --- | --- |
| `--shell` | `#4a2c1d` | 栗の皮 (いちばん暗い茶色。文字や線の色) |
| `--shell-light` | `#7a4a2b` | 栗の皮の明るいところ |
| `--marron` | `#c99a6b` | モンブランのクリーム (マロン色) |
| `--marron-light` | `#e8cba3` | クリームの明るいところ |
| `--cream` | `#fff4e2` | 生クリーム、ウィンドウの紙の色 |
| `--maple` | `#c8442f` | 紅葉の赤 |
| `--ginkgo` | `#e8b23a` | 銀杏・紅葉の黄色 |
| `--dusk` | `#f0a57a` | 秋の夕暮れの空 |
| `--link` | `#2f6f8f` | リンク色。函館の海の青を少しだけ使う |

- 本文の文字は `--shell` を `--cream` の上に置き、コントラスト比 4.5:1 以上を確かめます。
- 部品の CSS では生の色の名前ではなく、役割のトークン (`--ink`、`--window`、`--frame` など) を使います。

## 文言と表記

- サイトの文言は日本語です。
- 名前は `まろん｡` です。キャッチコピーは「便利とロマンをシェアしよう」「思い立ったが吉日」で、一字一句このまま使います。
- 名前とアイコンは otoneko.cat と同じくウィンドウの外 (ヒーロー) に出します。名前の下の文は「よわよわ園児にゃー」で固定し、切り替えません。
- X ではなく `Twitter` と表記します。
- 市電の停留所の札は「電停」です。行き先の電光掲示板は付けません。
- otoneko.cat への入口は「趣味垢はこちら」と直接案内し、リンクは otoneko.cat だけにします (Twitter は載せません)。「もうひとりのわたし」のような言い回しは使いません。
- フッターは左下に「© まろん｡」、右下に Contact だけを置きます。年や All rights reserved. は書きません。PixelMplus の © は字形が崩れるので、© はドット絵で描きます。
- 海の上に船やブイなど浮かぶものは置きません。函館山のふもとに教会などの白い建物は描きません。
- 文言は短くし、余計な説明を足しません。自己紹介のニュアンスは本人の言葉を優先します。
- ボタンやリンクの文言は英語の短い語にします (`Link`、`More`)。
- UI に出すパスはスラッシュ区切りです。
- 所属、学年、経歴などの変わる情報は `src/data/profile.ts` に集め、部品の中には書きません。

## 載せる内容

- GitHub から取れるデータ (統計、作品、コントリビューション) は手書きしません。リクエスト時に取得します。
- 作品の説明文は GitHub の Description をそのまま表示し、カードでは2行で省略します。`Link` は GitHub の Website 欄から取ります。
- 道の両端の縁石の上にガス灯を並べます。点いたら灯ったままにし、点滅させません。
- Works、Contributions、Blog の件数と並び順は portfolio-v3 に合わせます。Works はピン留め (📌のドット絵) のあとにスター順の上位9件、Contributions はスター数の多い順 (不明は最後、同数なら PR と Issue の合計順)、Blog は新しい順に30件で、1週間以内の記事に New を付けます。
- スター、マージ済み PR、Issue の数は、行の右側にドット絵のアイコン付きで縦に並べます。数がないときは `-` です。
- otoneko.cat への入口は、アカウント一覧の1行にせず独立した枠にします。文言は otoneko.cat 側 (`otnc-portfolio-v3` の `src/data/profile.ts` と `BottleMail.astro`) と食い違わないようにします。
- アクセスカウンターは置きません。
- SNS は GitHub (otnc、oto-lab)、Twitter、Misskey、mixi2、Instagram です。WakaTime、SoundCloud、Spotify、Discord は載せません。SNS 欄は2列までにします。
- GitHub の言語の割合は全言語を表示します。
- 並びは今の montblank.fun に合わせなくて構いません。今は Profile (about) の次に Blog を置いています。

## ドット表現

- ドット絵 (アイコン、スプライト、背景の飾り) の1ドットは 3px にそろえます (CSS の `--dot`)。例外は自分のアイコンのディザだけです。
- ドット絵は回転させたり、整数倍以外に拡大縮小したりしません。
- 文字は PixelMplus をマス目の整数倍で使います。本文は PixelMplus10 を 20px、見出しは PixelMplus12 を 24px と 48px です (スマホでは 36px)。欧文も同じフォントです。
- 枠の角はドットの欠けた形を保ちます。`box-shadow` で角を四角く塗らず、影は `filter: drop-shadow()` で付けます。
- 色の境目の凸凹は、なめらかにうねる線にします。ザラザラした点描にはしません。

## 動き

- アニメーションは惜しまず、たくさん、凝って入れます。otoneko.cat 以上に動くサイトを目指します。
  - 背景は常に何かが動いている状態にします。
  - ウィンドウの開閉、ホバー、スクロールで現れる要素など、操作や表示のたびに反応を返します。
  - ドット絵のスプライトはコマ送りのアニメーションにします。
- アニメーションは基本的に `steps()` でカクカク動かします。例外は流れるメッセージのバナーで、`linear` でなめらかに、継ぎ目なく流し、最初は先頭のメッセージを画面中央に置きます。
- `prefers-reduced-motion` のときは、ループするアニメーションを止めます。
- 画面外のループアニメーションは止めます (`.is-paused`)。
- 動きを増やしてもページの軽さは守ります。重くなったら、質を落とさずに軽くする方法を先に探します。

## 技術

- Tailwind は使いません。React も、必要になるまで入れません。
- 共通の CSS は `src/styles/dusk.css`、部品だけのものは各 `.astro` の `<style>` に置きます。
- 部品はセクションごとに分け、ページは部品を並べるだけにします。
- Cloudflare は `devuloper` アカウントを使います。`mofumofupop` アカウントは使いません。
- 正規のドメインは `montblank.fun` (www なし) です。`www.montblank.fun` は 301 で転送します。
- `blog.montblank.fun` など他のサブドメインは、このリポジトリでは触りません。

## リポジトリ

- コード、識別子、コメント、コミットメッセージは英語です。ドキュメント (`docs/`) は日本語です。
- コミットに `Co-Authored-By` などの生成ツールの署名は付けません。
- コミットは変更の単位ごとに細かく分け、ドキュメントは実装と同じコミットで更新します。
